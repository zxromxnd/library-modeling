# Специфікація ER-моделі бібліотеки

## S1. Намір і межі
Описати дані невеликої бібліотеки паперових книг: видання, авторів, фізичні примірники, читачів та історію видач і повернень. Створити декларативну ER-модель Mermaid `erDiagram` або PlantUML і читабельний рендер з її вихідного тексту. Не моделювати SQL DDL/ORM, бронювання, сповіщення, штрафи, оплату, закупівлі, ремонт, втрату, списання та кілька філій.

## S2. Сутності й атрибути
`int` — ціле число, `string` — текст, `date` — календарна дата без часу. PK — первинний ключ, FK — зовнішній ключ. Усі поля обов’язкові, крім позначених `?`; відсутність значення означає невідомі або ще не наявні дані.

| Сутність | Атрибути |
|---|---|
| Читач | `reader_id: int PK`, `given_name: string`, `family_name: string`, `phone: string` |
| Автор | `author_id: int PK`, `given_name: string?`, `family_name: string?`, `pen_name: string?` |
| Видання | `edition_id: int PK`, `title: string`, `language: string`, `publication_year: int?`, `publisher_name: string?` |
| Примірник | `inventory_number: int PK`, `edition_id: int FK → Видання.edition_id` |
| Видача | `loan_id: int PK`, `reader_id: int FK → Читач.reader_id`, `inventory_number: int FK → Примірник.inventory_number`, `issued_on: date`, `due_on: date`, `returned_on: date?` |

## S3. Зв’язки та правила
Видання описує конкретне видання книги; примірник — фізичний об’єкт. Видання має **від 1 до багатьох** примірників, кожен примірник належить **рівно 1** виданню; видані читачам примірники також враховуються. Видання має **від 0 до багатьох** зазначених авторів, автор пов’язаний з **від 1 до багатьох** виданнями; це прямий зв’язок «багато до багатьох», без сполучної таблиці. Невідоме авторство означає відсутність зв’язку.

Читач і примірник мають кожен **від 0 до багатьох** видач за всю історію. Кожна видача стосується **рівно 1** читача та **рівно 1** примірника. Реєстрація читача може зберігатися без першої видачі. Читач може мати кілька незавершених видач різних примірників без числового ліміту. Примірник має **не більше 1 незавершеної видачі** одночасно. Видача незавершена, якщо `returned_on` відсутня. Повернення заповнює цю дату; історія зберігається. Окремої сутності повернення та збереженого статусу доступності немає: примірник доступний, якщо незавершена видача відсутня.

## S4. Критерії прийняття
- **AC1. Повнота:** модель містить рівно п’ять сутностей із S2; назви, типи, обов’язковість атрибутів і кардинальності відповідають S2–S3. Обмеження, які нотація не виражає, наведені текстовими примітками до моделі.
- **AC2. Ключі:** усі PK — додатні цілі числа, унікальні в межах своєї сутності. FK мають тип відповідного PK та посилаються на наявні записи. Інвентарний номер є PK без додаткового ID примірника.
- **AC3. Текстові дані:** обов’язкові текстові значення непорожні. В автора заповнене щонайменше одне з полів імені, прізвища або псевдоніма; псевдонім один або відсутній. Телефон текстовий, не обов’язково унікальний. Невідомі дані не замінюються текстом «невідомо» або вигаданими значеннями; відомий рік видання більший за нуль.
- **AC4. Дати:** `due_on ≥ issued_on`; за наявності `returned_on ≥ issued_on`. Повернення в день видачі дозволене. `returned_on > due_on` означає прострочення, але не забороняє повернення; повернення у планову дату своєчасне.
- **AC5. Видачі:** повторна видача вже виданого примірника недопустима. Три примірники одному читачеві утворюють три видачі; повернення одного не завершує решту.
- **AC6. Нормалізація:** опис видання не дублюється у примірниках, дані читача — у видачах; автори не зберігаються списком у полі. Видача має власні дати та є змістовною асоціативною сутністю. Похідна доступність не зберігається окремо.
- **AC7. Рендер:** діаграма відтворює актуальний декларативний текст; підписи, ключі та кардинальності читабельні, зв’язки візуально розрізняються.
